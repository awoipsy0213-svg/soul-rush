## 1. コンセプト

モンスターと魂を組み合わせ、30秒間の戦闘を極める。
短時間の自動戦闘、成果報酬、強化、再挑戦を繰り返す。プレイヤーの戦略は戦闘前のビルドに集中させる。参考作品は Rune Rider とし、名称・素材・コードは独自に作成する。

### ユーザーの指定に基づく確定事項

- 最大30秒のステージ制。全敵撃破でクリアし、次のステージへ進む。
- 味方は左側、敵は右側の列に配置。先頭の敵を倒すとすぐ次の敵が対象になる。ステージごとに敵数が異なる。
- 失敗しても撃破割合に応じた報酬。全敵撃破で追加のクリア報酬。
- モンスターの種類によって攻撃力、攻撃速度、能力枠、習得可能な能力が異なる。
- 敵を倒してモンスターを育て、魂を獲得し、能力構成を工夫する。
- ロード画面、タイトル画面、戦闘、ビルド、購入画面を備える。
- シンプル設計。機能を増やすより戦闘・育成・編成・購入を完成させる。

以下の詳細は、現行実装と直前の設計案を踏まえて開発を進めるための作業基準。数値と例外的な仕様を含め、ユーザーが個別承認した最終仕様ではない。変更はこの文書に理由を記録してから実装する。

## 2. 戦闘とステージ

| ID | ルール |
|---|---|
| B01 | 出撃モンスターは1体。完全自動攻撃。味方HP・防御・スタミナ・戦闘中の手動スキルは設けない。 |
| B02 | 戦闘開始時にモンスター、攻撃力、攻撃速度、装着魂とレベルを固定。戦闘中に構成を変更しない。 |
| B03 | 通常攻撃は先頭の生存敵に対して実行。撃破後、待ち時間なしで次の敵が対象となる。次の通常攻撃自体は攻撃間隔に従う。 |
| B04 | 30秒以内に全敵撃破で即終了・クリア。30秒ちょうどの攻撃も有効。未撃破の敵が残っていれば時間切れ。 |
| B05 | 再挑戦時は全敵HP、撃破数、攻撃回数、魂の戦闘内効果、タイマーを初期化。恒久的な育成・所持品は維持。 |
| B06 | 解放済みステージに何度でも挑戦可能。クリア済みのステージの再挑戦も可能。解放進捗は後退しない。 |
| B07 | 通常攻撃の余剰ダメージは原則消失。貫通の魂など固有効果のみが後続に影響する。 |
| B08 | 敵の差別化はまずHPと敵数。通常・少数高HP・多数低HP・ボスを組み合わせる。 |

攻撃速度の単位は回/秒。攻撃間隔は1/攻撃速度（秒）。初回通常攻撃は1攻撃間隔経過後。効果の発動時刻が一致する場合は現行の通常攻撃→攻撃回数型追加攻撃→爆炎→月蝕の順で処理する。時間型と通常攻撃が30秒ちょうどに発動する場合も処理対象。

## 3. モンスター

- 表示する戦闘ステータスは攻撃力（ATK）と攻撃速度（SPD）の2種類。
- 種類固有の基本ATK、基本SPD、魂枠、魂適性。所持個体ごとにLv・経験値・装着構成を保持。
- 出撃した1体だけが経験値を得る。育成でATKとSPDが上昇。重複個体・装備品・別のプレイヤーレベルは設けない。
- モンスターは通貨で1回だけ購入・解放。購入後は自由に切り替え可能。価格差がそのまま上位互換にならないよう後で調整。
- 現行の4種類（モス、ヴォルフ、グラント、イグニス）は検証用。新規追加より個性の確立を優先する。

## 4. 魂（能力）

- 魂は固有のアイコンを持つ共通所持品。1種類につき1つのレベルを管理。
- モンスターの魂枠に装着。適性のない魂や枠数超過は不可。同じ魂を同一モンスターに重複装着しない。
- 構成はモンスター別に保存。未出撃のモンスターとの装着競合は設けない。付け替え無料。
- 獲得は累計撃破数の到達報酬と通貨による購入。重複獲得・追加購入で魂Lv上昇。ランダム抽選は当面導入しない。
- 効果は常時型、攻撃回数型、時間型、撃破型を軸にし、貫通のような特殊な常時効果も扱う。

| 現行の魂 | 発動 | 役割 |
|---|---|---|
| 力 | 常時 | ATK上昇 |
| 疾風 | 常時 | SPD上昇 |
| 雷鳴 | 通常攻撃4回ごと | 追加攻撃 |
| 爆炎 | 5秒ごと | 先頭3体への範囲攻撃 |
| 捕食 | 敵撃破 | 戦闘中ATK上昇（上限あり） |
| 貫通 | 通常攻撃 | 余剰ダメージの一部を後続へ |
| 月蝕 | 10秒ごと | 高威力攻撃 |

効果の具体的倍率、発動間隔、習得適性、Lv上限はバランス調整対象。7種類の効果の現行ルールは維持して検証する。

## 5. 報酬・経済・育成

通貨は1種類（仮称エーテル）。リアルマネー、広告、プレミアム通貨は対象外。

- 撃破割合報酬 = floor(ステージ基準報酬 × 撃破数 / 敵総数)
- クリア追加報酬 = 全敵撃破時のステージ追加報酬。失敗時は0。
- 総報酬 = 撃破割合報酬 + クリア追加報酬。
- 経験値 = 撃破数。現行の1体あたり1XPは仮数値。
- 戦闘終了時に報酬、経験値、累計撃破報酬、解放進捗を一度だけ確定する。
- 未終了の戦闘を中断・再読込した場合は未確定の結果を付与しない。
- 撃破0体なら報酬・経験値0。難しいステージは解放済みの旧ステージを活用できる設計とし、初期段階で行き詰まらないことを後続のバランス試験で確認。
- 再クリア時にもクリア追加報酬を付与する現行ルールを作業基準とする。短時間周回の報酬効率は要検証。初回限定に変更する場合は別途仕様変更を記録。

例: 敵20体、基準報酬100、クリア追加50。12体撃破なら60。全20体撃破なら150。具体的な敵数、報酬、成長率、必要XP、購入価格、魂入手マイルストーンは仮設定。

## 6. 画面

メインは3画面。タイトルとロードは導入、設定は補助。

| 画面 | 必須の情報・操作 |
|---|---|
| 戦闘 | ステージ、残り時間、撃破数/総数、味方と敵の列、魂発動、開始。結果には成否・報酬・成長・獲得魂と再挑戦/次ステージ。 |
| ビルド | モンスター選択、Lv、ATK、SPD、魂枠、所持魂・効果・適性。装着と解除。 |
| 購入 | 所持通貨、モンスター購入、魂購入・強化。価格・現在Lv・効果の明示。 |
| 補助 | ステージ一覧・戦績は戦闘画面から、セーブの出力/復元は設定から。 |

UI改善方針: iPhone縦画面優先。戦闘画面の上部に残り時間・撃破数、中央に戦闘、下部に主操作を集約。戦績・長い説明は必要時に開く。3画面の遷移を増やさない。旧機能やデータは無断で削除しない。戦闘中は購入・編成変更・ステージ変更を禁止する。

## 7. 保留・対象外

属性相性、レアリティ、進化、スキン、複数体編成、ガチャ、デイリー、オンラインは保留。防御、味方HP、MP、装備品、スタミナは現在の基本設計の対象外。追加前にコアの面白さを検証する。

## 8. 技術とデータ

- Web版は現在のGitHub Pages URLを維持。静的HTML/CSS/JSを使用し、不要なライブラリを追加しない。
- 戦闘エンジンとUIの責務を分離。戦闘ルールの回帰テストを維持する。
- 保存キー soul_rush_prototype_v1、バージョン1を維持。データ形式を変更する場合は旧セーブ移行と破損時保護を事前検証。
- 30秒の境界、敵の即時切替、戦闘中断、再挑戦の初期化、戦闘開始時の構成固定、二重付与、繰返しクリア、0体撃破を回帰テストで確認。
- 今回はゲーム本体・保存形式・公開PWA設定に変更なし。実装検証済みのルールと、今後実装するUI改善案を混同しない。
